# 5_workflow_auth-api-integration_260517Sun.md

## 1. 개요
- **목표:** 백엔드에 기구현된 인증 로직(회원가입, 로그인, 로그아웃, 세션 확인)을 프론트엔드와 연동하기 위한 워크플로우를 정의한다.
- **주요 작업:**
  - 기존 프론트엔드의 하드코딩된 Mock 데이터/로컬 스토리지 방식을 제거하고 실제 백엔드 API 호출로 교체한다.
  - 브라우저 쿠키(`JSESSIONID`)를 통한 세션 기반 인증이 프론트와 백엔드(다른 포트/도메인) 간에 정상적으로 유지되도록 백엔드 CORS 및 프론트엔드 `fetch` 설정을 완료한다.
  - 전역 로그인 상태 관리 로직을 연동하고, 로그인/로그아웃 시나리오를 통합 테스트한다.

---

## 2. 사전 체크 및 백엔드 설정 점검
- [x] 백엔드 `WebConfig.java`의 CORS 설정 확인
  - [x] `allowedOrigins`에 프론트엔드 로컬 주소(예: `http://localhost:5173`)가 명시되어 있는지 확인
  - [x] `allowCredentials(true)` 설정이 되어 있어 세션 쿠키가 양방향으로 전달될 수 있는지 확인
- [ ] 프론트엔드 환경 변수(`.env`)에 API Base URL(예: `VITE_API_BASE_URL=http://localhost:8080`)이 설정되어 있는지 확인

---

## 3. 상세 작업 To-Do (프론트엔드 연동 절차)

### 3.1. API 호출 공통 유틸리티 구성
- [x] `fetch` 또는 `axios` 설정에 `credentials: 'include'` 옵션이 기본으로 포함되도록 래퍼(Wrapper) 함수 구성 (세션 쿠키 전달에 필수)
- [x] 인증 관련 API 엔드포인트 호출 함수 세팅:
  - [x] `POST /api/auth/register` (회원가입)
  - [x] `POST /api/auth/login` (로그인)
  - [x] `POST /api/auth/logout` (로그아웃)
  - [x] `GET /api/auth/me` (현재 로그인된 사용자 정보 조회)

### 3.2. 회원가입 기능 연동
- [x] 프론트엔드 회원가입 폼 제출(Submit) 이벤트를 실제 `POST /api/auth/register` API 호출 로직으로 교체
- [x] 백엔드 커스텀 에러(`AuthException`, 중복 이메일 등) 응답을 파싱하여 화면에 에러 메시지를 표시하는 핸들링 로직 추가
- [x] 가입 성공 시 로그인 페이지로 자동 리다이렉션 처리

### 3.3. 로그인 및 전역 상태 연동
- [x] 프론트엔드 로그인 폼 제출 시 `POST /api/auth/login` API 호출 로직으로 교체
- [x] 로그인 성공 시, 응답받은 `UserResponse` 데이터(id, email, nickname 등)를 프론트엔드 전역 상태(Context API 등)에 저장
- [ ] 크롬 개발자 도구(Network, Application 탭)에서 응답 헤더의 `Set-Cookie`를 통해 `JSESSIONID`가 브라우저에 정상적으로 저장되는지 확인

### 3.4. 인증 유지 (자동 로그인 / 세션 복구)
- [x] 프론트엔드 앱 초기 로드 시(App 마운트 시), 가장 먼저 `GET /api/auth/me`를 호출하여 유효한 세션이 존재하는지 확인
- [x] 유효한 사용자 응답이 오면 전역 상태에 복원하여 로그인 상태를 유지(헤더 UI 변경 등)
- [x] 세션 만료 또는 미로그인 시(`401 Unauthorized` 상태 코드 반환), 전역 상태를 빈 값으로 초기화

### 3.5. 로그아웃 기능 연동
- [x] 네비게이션 바(Navbar)의 로그아웃 버튼 클릭 시 `POST /api/auth/logout` API 호출
- [x] 로그아웃 API 호출 성공 후, 프론트엔드의 전역 로그인 상태를 즉시 초기화
- [x] 홈(F-08 랜딩) 또는 로그인 페이지로 사용자 리다이렉션 처리

## 4. 로컬 테스트 및 통합 검증
- [ ] 인증이 필요한 보호된 API(예: 관심 동물 등록 등) 호출 시, 요청 헤더에 세션 쿠키가 잘 실려가는지 확인
- [ ] 프론트엔드 화면에서 [회원가입 -> 로그인 -> 페이지 새로고침(로그인 상태 유지 확인) -> 로그아웃] 시나리오가 끊김없이 동작하는지 E2E 테스트
- [ ] 로그인하지 않은 상태에서 인터셉터(`LoginCheckInterceptor`)가 적용된 API 접근 시, 401 에러를 프론트가 정상적으로 Catch하여 로그인 유도 팝업이나 페이지로 보내는지 검증
