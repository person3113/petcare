프로젝트 개요
서비스명: 유기동물 입양 플랫폼 (웹 서비스)
목적: 한국 공공 API를 활용하여 유기동물 정보 조회, 입양 관리, 통계 시각화 기능을 제공하는 반응형 웹 애플리케이션 개발

수업 및 평가 맥락
이 프로젝트는 대학교 3학년 1학기 "오픈소스 웹소프트웨어" 수업의 기말 팀 프로젝트이며, 총 30점 배점으로 아래 기준으로 평가됩니다:

항목	배점	핵심 포인트
Planning & Project Idea	5점	기획 구체성, ERD/API 설계
User Interface	10점	HTML/CSS, 반응형, 시각적 완성도
Completion	10점	JavaScript 비중, DB 연동, 실제 동작
English Presentation	5점	내용 전달력 중심, 발음보단 자신감
JavaScript가 프로젝트의 가장 중요한 요소로 명시됨 — JS/TS/React.js의 비중을 크게 가져가야 함

교수님 성향: 시각적으로 attractive한 UI 선호, 기능 수보다 UI 완성도와 JS 활용도를 중점 평가

AI로 생성한 코드 복붙하는 걸 교수가 싫어함.  

기술 스택

DB: 팀 합의에 따라 결정 (h2, Supabase 등 검토됨)

버전관리: Git (브랜치 전략: main ← dev ← feature/xxx)

AI 에이전트 참고용 핵심 요약 문서 (2026.03 Q&A 기반)

다른 팀과 주제가 겹쳐도 불이익 없음 — 각 팀의 퀄리티로 평가

핵심은 "functional하게" 만드는 것

2. 완성도 (10점) — 가장 중요
   기능 수가 많을수록 유리 — 중간발표 때 기능 리스트업 후, 최종까지 다 구현하면 OK

중간에 계획보다 기능 늘리면 플러스, 못 넣으면 이유 납득시키면 OK (꼭 필요한 기능 누락은 감점)

JavaScript 비중이 낮으면 감점 — HTML/CSS 위주인데 JS가 적으면 점수 하락

단순히 예쁜데 클릭하면 끝인 사이트 → 완성도 낮음

백엔드도 완성도에 포함되지만, CSS/JS 등 전반을 봄

3. UI (점수 내 포함)
   디자이너 수준 아니어도 되지만, 기본적인 common sense는 필요

감점 사례: 폰트가 위는 엄청 크고 아래는 너무 작은 경우, 들쭉날쭉한 여백, 기본 UI 무시

Responsive Web(모바일 대응) — 안 하면 나중에 지적함, 하면 플러스

5. 백엔드
   DB-프론트 연결이 잘 되는지 + 쿼리 정도 봄 — 복잡한 백엔드 불필요

테이블 4~5개 수준으로 충분 — 너무 복잡하게 할 필요 없음

Spring Data JPA(자동 쿼리) < 일반 JPA(직접 쿼리) — 후자가 더 열심히 한 것처럼 보임, 점수 차 소폭 있음

6. 코드 퀄리티
   허술해도 직접 짠 코드 선호 — 20년차 개발자 기준이 아님

CSS inline 남발 등 기본도 안 지키면 감점 가능

AI에게 리팩토링 팁 묻고 스스로 개선하는 건 허용

복붙(블로그, 오픈소스 코드 그대로) 취지상 비권장 — 참고만

7. 외부 서비스 / 툴 / AI 활용
   개발 보조 서비스, 툴 모두 사용 가능 (Bootstrap, Tailwind, Shadcn, Firebase, Supabase 등)

React 같은 라이브러리 CDN/npm으로 가져다 쓰는 것 OK

AI 코드 생성 직접은 금지 — 설계(ERD, API 명세 등) 문서 작성에 AI 활용은 OK

블로그/공식 문서 참고 후 직접 적용하는 방식 OK (그대로 복붙은 비권장)

9. 실전 전략 요약
   기능을 많이, 다 작동하게 만드는 게 제1 우선순위

JavaScript 코드를 충분히 활용 (단순 HTML/CSS만 내면 감점)

기본 UI 규칙 지키기 (폰트 크기 위계, 여백 일관성)

Responsive Web은 가능하면 구현 — 안 하면 나중에 지적받음

백엔드는 간단하게, 직접 쿼리 일부 작성

영어 발표는 4분씩 분담, 암기 도전

AI는 설계 문서/리팩토링 팁에만 활용, 코드 직접 구현
