# **Must 범위 API 목록 (F-01 ~ F-08)**

아래 표는 **프론트가 직접 호출하는 내 백엔드 API**와 **백엔드가 공공 API를 대신 호출하는 내부 처리**를 구분해서 작성했습니다. 이 구분이 중요한 이유는, 공공 API 키는 백엔드에서만 관리하고 프론트는 절대 직접 호출하지 않아야 하기 때문입니다.

---

## **📌 표 읽는 법 먼저**

- **No.**: API 번호 (연관 기능 ID 포함)
- **Method**: HTTP 메서드 (GET/POST 등)
- **Endpoint**: 내 백엔드 URL 경로
- **역할**: 이 API가 하는 일
- **호출 주체**: 누가 이 API를 부르는가
- **연결 공공 API**: 내 백엔드가 내부적으로 호출하는 외부 API

## **🐾 [A] 구조동물 관련 (F-01, F-02, F-03, F-04)**

| **No.** | **Method** | **Endpoint** | **역할** | **호출 주체** | **연결 공공 API** |
| --- | --- | --- | --- | --- | --- |
| A-1 | GET | `/api/animals` | 구조동물 목록 조회 (필터 파라미터 포함) | 프론트 | 공공 구조동물 조회 또는 DB 캐시에서 반환 |
| A-2 | GET | `/api/animals/:desertionNo` | 구조동물 단건 상세 조회 | 프론트 | DB 캐시 우선, 없으면 공공 API 호출 |
| A-3 | POST | `/api/animals/sync` | 공공 API에서 최신 데이터 받아 DB에 동기화 | 관리자 (수동 호출) | 공공 구조동물 조회 API |

| **파라미터명** | **예시 값** | **설명** |

## **🔍 [C] 필터 드롭다운용 코드 조회 (F-02)**

시도 → 시군구 → 보호소 연쇄 드롭다운을 위한 API입니다. 이 데이터는 거의 변하지 않으니 **서버 시작 시 1회 캐싱**하면 충분합니다.

| **No.** | **Method** | **Endpoint** | **역할** | **호출 주체** | **연결 공공 API** |
| --- | --- | --- | --- | --- | --- |
| C-1 | GET | `/api/codes/sido` | 시도 목록 조회 | 프론트 (드롭다운) | 공공 구조동물 `/sido` |
| C-2 | GET | `/api/codes/sigungu?uprCd=` | 시도 선택 후 시군구 목록 조회 | 프론트 (드롭다운) | 공공 구조동물 `/sigungu` |
| C-3 | GET | `/api/codes/shelters?uprCd=&orgCd=` | 시군구 선택 후 보호소 목록 조회 | 프론트 (드롭다운) | 공공 구조동물 `/shelter` |

> **⚠️ Debounce 필수: 드롭다운 변경마다 C-2, C-3을 연쇄 호출하면 API 한도를 낭비합니다. 300ms debounce를 꼭 붙이세요.**

## **🧩 [E] 설문 기반 매칭 (F-05)**

설문 자체는 프론트 JS 로직(5문항 응답 → 파라미터 변환)이고, 결과 조회는 A-1을 재사용합니다.

| **No.** | **Method** | **Endpoint** | **역할** | **호출 주체** |
| --- | --- | --- | --- | --- |
| E-1 | POST | `/api/match/quiz` | 설문 응답 5개 받아 → 추천 동물 리스트 반환 | 프론트 |

내부적으로 E-1은 설문 파라미터(`upkind`, `sex_cd`, `neuter_yn`, `upr_cd`, `state`)를 변환해서 A-1과 동일한 구조동물 DB 쿼리를 실행합니다. 별개 API가 아니라 쿼리 변환 레이어 하나를 씌우는 개념입니다.

## **📊 [G] 랜딩 통계 (F-08)**

통계 데이터는 `bgnde/endde` 날짜 범위를 코드에 하드코딩해서, 서버 시작 시 1회만 공공 API를 호출해 DB/메모리에 저장합니다.

| **No.** | **Method** | **Endpoint** | **역할** | **호출 주체** | **연결 공공 API** |
| --- | --- | --- | --- | --- | --- |
| G-1 | GET | `/api/stats/summary` | 랜딩 CountUp용 숫자 데이터 (총 구조수, 입양수 등) | 프론트 | 공공 통계 `/rescueAnimalStats` (se=chart1) |
| G-2 | GET | `/api/stats/chart` | 처분결과별 건수 (chart1) + 지역별 비율 (chart2) | 프론트 | 공공 통계 `/rescueAnimalStats` (se=chart1,chart2) |

G-1과 G-2는 실제로는 같은 공공 API 한 번 호출로 데이터를 가져온 뒤, 용도에 따라 내 백엔드에서 가공해서 나눠 주는 구조입니다.
