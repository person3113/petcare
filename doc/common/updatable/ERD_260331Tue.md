# ERD 초안

> 260331Tue

260330Mon 기능명세를 다 읽었습니다. 이전 최종안 대비 **ERD에 실제로 영향을 주는 변경은 S-5(커뮤니티)뿐**입니다. 먼저 그 분석부터 정리합니다.

---

## **이전 ERD 대비 변경 분석**

| **신규 기능** | **ERD 변경 여부** | **이유** |
  | --- | --- | --- |
| **S-5** 커뮤니티 (게시글+댓글) | ✅ **테이블 2개 추가** | POSTS, COMMENTS 신설 필요 |
| **S-6** 비슷한 아이들 추천 | ❌ 변경 없음 | ANIMALS 테이블 그대로 쿼리 재활용 |
| **S-7** 설문 기록 탭 | ❌ 변경 없음 | SURVEY_RESULTS 이미 존재 |
| **O-5** 입양 신청 절차 | 🔶 점선 테이블 1개 | Optional, 축소 버전만 설계 병기 |

## **ERD 최종안 (Must + Should 범위, 9 + Optional 1)**

## **전체 관계 구조**

`USERS ──────────< FAVORITES            (1:N)
USERS ──────────○ SURVEY_RESULTS       (1:0~1)
USERS ──────────< POSTS                (1:N)  ← S-5 신규
POSTS ──────────< COMMENTS             (1:N)  ← S-5 신규
USERS ──────────< COMMENTS             (1:N)
SHELTERS ───────< ANIMALS              (care_reg_no 소프트 참조)
ANIMALS.desertion_no ← FAVORITES      (소프트 참조, DB FK 없음)
RESCUE_STATS_CACHE                     (독립 캐시)
LOST_ANIMALS                           (독립 캐시)
[ADOPTION_APPLICATIONS]                (Optional O-5, 점선)`

## **⑥ POSTS ← S-5 신규 추가**

`sqlCREATE TABLE posts (
id          BIGINT AUTO_INCREMENT PRIMARY KEY,
user_id     BIGINT       NOT NULL,
category    VARCHAR(20)  NOT NULL,          -- 'adoption_review' | 'lost_sighting'
title       VARCHAR(200) NOT NULL,
content     TEXT         NOT NULL,
created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
updated_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
ON UPDATE CURRENT_TIMESTAMP,

  INDEX idx_category    (category),
  INDEX idx_user_id     (user_id),
  INDEX idx_created_at  (created_at),
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);`

- `category` 두 값만으로 충분합니다. 인기글 알고리즘·좋아요 수 등 복잡한 컬럼은 명세에서 제거 확정이므로 제외합니다.

## **🔶 [Optional] ADOPTION_APPLICATIONS (O-5, 점선 테이블)**

구현 여부 미확정이지만, 나중에 추가할 때 ALTER 없이 붙일 수 있도록 설계만 병기합니다.

`sql-- O-5 Optional, 축소 버전 (신청 제출 + 상태 뱃지만)
CREATE TABLE adoption_applications (
id             BIGINT AUTO_INCREMENT PRIMARY KEY,
user_id        BIGINT      NOT NULL,
desertion_no   VARCHAR(30) NOT NULL,        -- 소프트 참조
status         VARCHAR(20) NOT NULL DEFAULT 'pending',
-- pending | approved | rejected
message        TEXT,                        -- 신청자 메모
created_at     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
updated_at     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
ON UPDATE CURRENT_TIMESTAMP,

  UNIQUE KEY uq_user_application (user_id, desertion_no),
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);`

> **명세 O-5 설명대로 "5단계 전부"가 아닌 `status` 컬럼 하나로 처리하는 축소 버전입니다. 관리자가 없으니 `approved`/`rejected` 전환은 프론트에서 임의 처리하거나 보호소 연락 버튼(F-04)으로 대체해도 무방합니다.**
