## **✅ Must — 중간발표에서 약속, 반드시 완성**

기존 명세 F-01~F-08 **전부 유지**. 변동 없음.

| **ID** | **기능** | **이유** |
  | --- | --- | --- |

## **🟡 Should — Must 완성 후 우선 추가, 중간발표 후 어필용**

## **기존 명세 Should (S-1~S-4) 유지**

| **ID** | **기능** | **우선순위 근거** |
  | --- | --- | --- |
| S-1 | 구조동물 통계 상세 차트 (Chart.js) | 교수님 시각화 선호 + JS 어필 = 일타쌍피 |

| S-3 | Gemini AI 1인칭 동물 소개글 | 발표 데모 "와" 포인트, AI 활용 사례 어필 |
| S-4 | 관심 동물 목록 페이지 | F-04 하트 저장과 연계, DB 연동 증명 |

## **🆕 와이어프레임에 있던 것 중 Should로 신규 추가**

**S-5: 커뮤니티 기본형**

- 입양후기·분실목격 카테고리 중심, 게시글 CRUD + 댓글
- 이유: 기능 수를 한 번에 4~5개 늘릴 수 있음 (목록/작성/상세/댓글 = JS 풍부), 교수님 "기능 많으면 완성도 업" 발언과 직결
- 단, 중간발표에서 약속하지 않고 **최종 발표 때 추가로 어필**하는 전략 권장
- 복잡한 부분(인기글 알고리즘, 글쓴이 프로필 사이드바 등)은 제거하고 단순 CRUD만 구현

**S-6: 동물 상세 "비슷한 아이들" 추천 섹션**

- 이유: F-02 필터 로직 거의 그대로 재활용, 추가 공수 낮음, UX 완성도 높아 보임

**S-7: 마이페이지 설문 기록 탭**

- F-05 설문 결과를 저장해서 마이페이지에서 조회하는 기능
- 이유: DB 연동 사례 하나 더 추가, 공수 낮음, "내가 어떤 조건으로 매칭받았는지" 확인 = 자연스러운 UX

## **🔵 Optional — 시간과 여력 남을 때만**

## **기존 명세 Optional 유지**

- 카카오/구글 소셜 로그인 (+ 네이버도 같이 묶기)
- 보호소 마커 → 동물 목록 연동
- 반려동물 동반 여행 지도 레이어
- AI 입양 상담 챗봇 (단발형 Q&A)

## **🆕 와이어프레임에 있던 것 중 Optional로 분류**

**O-5: 입양 신청 절차 다단계 플로우** (5단계: 신청→서류검토→심사→방문→완료)

- 이유: 파일 업로드 + 상태 머신 + 일정 예약 = 공수 매우 큼. 교수님 "복잡한 기능 한 두 개에 시간 붙잡지 말고"와 정면으로 충돌. F-04의 "입양 신청하기 → 보호소 연락" 버튼으로도 기능상 충분함
- 만약 한다면: 5단계를 전부 구현하지 말고 "신청 제출 + 상태 뱃지(대기중/승인/거절) 표시" 정도로 대폭 축소

**O-6: 개인 맞춤 입양 준비 리포트 대시보드** ("지은님의 입양 준비 리포트")

- 이유: 레이더 차트, 도넛 차트, AI 인사이트, 개인 활동 통계 = 인상적이지만 의미 있는 데이터가 쌓여야 보임. S-1이 이미 시각화 역할을 담당. 두 번째 대시보드를 만들기엔 공수 대비 효율 낮음

**O-7: 입양 신청 서류 체크리스트 페이지**

- 이유: 정적 콘텐츠에 가깝고 JS 비중 거의 없음. 단, UX 완성도 측면에서 좋아 보임. 체크박스 상태 저장 정도로 최소화하면 공수 낮음

## **❌ 제거 확정 (기존 유지)**

| **기능** | **이유** |
  | --- | --- |
| 연속(출석) 스트릭 | 입양 서비스 성격과 불일치 |
| 관리자 대시보드 | DB 복잡도 vs 점수 효율 최하 |
| 실시간 채팅 (WebSocket) | 난이도 대비 평가 가산점 없음 |
| 챗봇 히스토리/세션 저장 | 복잡도만 키움 |
| 동물등록 정보조회 API | 실서비스 UX 성립 안 됨 |
| 반려동물 등록대행업체 조회 | 서비스 방향과 무관 |

- **Optional 7개**: Must+Should 다 끝나야 손 댈 수 있음, 특히 O-5 입양 절차 플로우는 축소 없이는 건드리지 않는 것 권장
